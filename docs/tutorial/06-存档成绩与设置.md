# 06 · 存档、成绩与设置

> 本篇目标：理解在无本地文件权限的引擎沙盒里如何做存档，以及成绩、设置、每日打卡的数据结构。

## 6.1 为什么不用本地文件

`scripts/game/storage.lua` 的头部注释记录了踩坑过程：

> 引擎沙箱禁止 `FileSystem:GetAppPreferencesDir`（会抛 "not allowed" 并被校验判错），项目目录在正式包里也未必可写。

所以存档只走 **`clientCloud` 云变量 + 内存兜底**：

```
写入 → 先写 memory_ → 再写 clientCloud.Set
读取 → 试 clientCloud.Get → 失败回落 memory_
```

## 6.2 检测云端是否真的可用

```lua
local function cloud()
    local c = rawget(_G, "clientCloud")
    if not c then return nil end
    local uid = c.userId
    if uid == nil or uid == "" or uid == 0 then return nil end
    return c
end
```

关键坑：**本地预览里 `clientCloud` 对象存在，但 `userId` 是占位值**。如果只看对象是否存在，会误以为云端可用，导致存档写到假云里。所以必须校验 `userId`。

## 6.3 读写实现

```lua
local SCHEMA = 1
local CLOUD_KEY = "sudoku_save_v1"   -- 当前进度
local STATS_KEY = "sudoku_stats_v1"  -- 成绩与设置

local memory_ = {}  -- 兜底

function Storage.write(key, data, onDone)
    memory_[key] = data              -- 无条件先写内存
    local c = cloud()
    if not c then return end
    pcall(function()
        c:Set(key, data, {
            ok = function() if onDone then onDone(true) end end,
            error = function() if onDone then onDone(false) end end,
        })
    end)
end
```

读取更复杂，因为 ClientCloud 的回调有两种成功路径：

```lua
function Storage.read(key, onLoaded)
    local c = cloud()
    if not c then
        onLoaded(memory_[key]); return
    end
    pcall(function()
        c:Get(key, {
            ok = function(values, iscores)
                local v = values and values[key]
                onLoaded(v or memory_[key])
            end,
            error = function() onLoaded(memory_[key]) end,
            timeout = function() onLoaded(memory_[key]) end,
        })
    end)
end
```

ClientCloud 约定：`Set` 写进 `values`，`SetInt` 写进 `iscores`。我们用的是 `Set`，所以从 `values[key]` 取值。

**降级后果要清楚**：云端不可用时只有内存存档，**应用重启后进度丢失**。这是平台限制，不是 bug。

## 6.4 清进度

```lua
function Storage.clearProgress()
    memory_[CLOUD_KEY] = nil
    local c = cloud()
    if not c then return end
    c:BatchSet():Delete(CLOUD_KEY):Save("clear sudoku save", {})
end
```

用 `BatchSet():Delete():Save()` 是 ClientCloud 的批量操作 API。注意**只清进度，不清成绩**——`STATS_KEY` 保留。

## 6.5 `isFiniteNumber`：nan 检测

```lua
function Storage.isFiniteNumber(v)
    if type(v) ~= "number" then return false end
    local s = tostring(v)
    return not (s:find("nan") or s:find("inf"))
end
```

引擎里 `nan > 0` 可能返回真，无法用常规比较检测。只能用字符串判定。`main.lua` 和 `board_view.lua` 都复用了这个函数（或同样的写法）来防御 Yoga 布局首帧返回的 nan 尺寸。详见第 10 篇。

## 6.6 成绩：`records.lua`

```lua
local VERSION = 3

function Records.new()
    return {
        v = VERSION,
        best = {},        -- { easy = {seconds, mistakes}, ... }
        cleared = 0,      -- 累计通关数
        daily = Daily.newState(),
        settings = Settings.new(),
    }
end
```

提交成绩的规则：**只有更快才刷新**：

```lua
function Records.submit(records, difficulty, seconds, mistakes)
    if seconds <= 0 then return false end
    local prev = records.best[difficulty]
    if not prev or seconds < prev.seconds then
        records.best[difficulty] = { seconds = seconds, mistakes = mistakes }
        return true, prev
    end
    return false, prev
end
```

`daily` 题不参与各档最佳——`main.lua` 的通关分支会判断 `board_.dailyKey`，每日局只记打卡，不刷新最佳成绩。否则一次简单的周一每日题就能刷掉专家档记录。

## 6.7 设置：`settings.lua`

```lua
local FONT_STEPS  = { 10, 11, 12 }
local LIMIT_STEPS = { 0, 3, 5 }   -- 0 = 不限
local DEFAULTS = {
    sound = true,
    autoClean = true,
    candidateFont = 11,
    mistakeLimit = 0,
}
```

`sanitize(data)` 的哲学：**非法值一律回落默认，且只允许步进值**。比如 `candidateFont=13` 会被纠正回 11，`mistakeLimit=4` 会被纠回 0。这样存档即使被手动改坏，也不会让 UI 崩掉。

设置内嵌在 `records.settings` 里，随 `saveStats` 一起落盘，不单独占一个 key。

## 6.8 异步回调的保护

`Storage.loadStats` 和 `Storage.load` 的回调**可能同步返回**。如果玩家在回调返回前已经开始落子，同步返回的旧存档会覆盖当前进度。

`main.lua` 的防护：

```lua
Storage.load(function(data)
    if saveDirty_ or (board_ and board_.started) then return end
    -- 隔天的每日存档也丢弃
    if data and data.daily and data.daily ~= Daily.today() then return end
    -- ... 才 restore
end)
```

三道闸门：`saveDirty_`（有未保存改动）、`board_.started`（已开局）、每日存档过期。

## 6.9 本篇小结

- 沙盒禁本地文件写入，存档只走 clientCloud + 内存兜底。
- 检测云端要看 `userId`，不能只看对象是否存在。
- 读写都先走内存，云端失败静默降级；清进度不能清成绩。
- `nan` 只能用字符串判定，常规比较不可靠。
- 成绩「更快才刷新」，每日题不参与最佳。
- 设置 sanitize 只允许步进值；异步回调要用 `saveDirty_` / `started` 保护。
