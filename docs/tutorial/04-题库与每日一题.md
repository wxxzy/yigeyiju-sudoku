# 04 · 题库与每日一题

> 本篇目标：理解离线题库的生成—验收—抽题流水线，以及如何用日期哈希实现「所有人今天同一道题」。

## 4.1 为什么需要离线题库

第 2 篇说过，生成一道符合难度要求的题可能要试几十次，专家档尤其贵（凑齐 20 道题试了 733 次）。如果玩家每次开新局都现场生成，手机上会明显卡顿。

解决方案：**离线生成 + 验收 + 内置题库**，运行时只做抽题。

```
gen_bank.lua（离线生成） → bank_check.lua（验收） → puzzle_bank.lua（内置数据）
                                                          ↓
                                              board.lua 抽题 / daily.lua 选题
```

## 4.2 题库结构

`scripts/game/puzzle_bank.lua`：

```lua
local TIERS = { "easy", "normal", "hard", "expert" }

local DATA = {
    easy = {
        "530070000600195000098000060800060003400803001700020006060000280000419005000080079",
        -- ... 每档 20 题
    },
    -- ...
}
```

- 每道题是 81 位字符串，`0` 表示空格。
- 每档 20 题（文件头注释写「8 题」是旧的，没同步更新）。
- `cache_[difficulty]` 缓存解析结果，`parse(str)` 逐字符 `tonumber`。

> 坑：注释和真实数据不一致。以后维护时以 `gen_bank.lua` 里的 `PER_TIER = 20` 为准。这类「注释腐化」在长期迭代的项目里很常见，教程如实保留了这个痕迹。

## 4.3 抽题：随机但不重复

```lua
function PuzzleBank.pick(difficulty)
    local list = DATA[difficulty]
    if not list then return nil end
    local n = #list
    local idx = math.random(1, n)
    if idx == lastPick_[difficulty] then
        idx = (idx % n) + 1  -- 避免连续两局同一题
    end
    lastPick_[difficulty] = idx
    return parse(list[idx])  -- 返回副本，防调用方污染缓存
end
```

`pickAt(difficulty, index)` 则按指定下标取题，用取模处理越界——这是每日一题的基础。

## 4.4 每日一题：确定性选题

目标：**全球玩家在同一天拿到同一道题**，即使他们用不同设备、不同时间打开。

`scripts/game/daily.lua` 的关键设计：

### 星期轮换难度

```lua
local WEEKDAY_DIFFICULTY = {
    [1] = "easy",    -- 周日
    [2] = "easy",    -- 周一：一周之始，轻松点
    [3] = "normal",  -- 周二
    [4] = "hard",    -- 周三
    [5] = "normal",  -- 周四
    [6] = "hard",    -- 周五
    [7] = "expert",  -- 周六：周末挑战
}
```

用 `os.date("*t", dayTime(key)).wday` 取星期几。

### 日期哈希选题

```lua
function Daily.hash(text)
    local h = 5381
    for i = 1, #text do
        h = (h * 33 + text:byte(i)) % 2147483647
    end
    return h
end

function Daily.indexFor(key, count)
    return (Daily.hash(key) % count) + 1
end
```

这是 djb2 哈希的变体。取模 `2147483647`（2³¹−1）是为了避免整数溢出后 Lua 用浮点数表示导致精度误差。同一个日期字符串永远得到同一个下标，因此**不需要服务端下发**。

### 中午取时间

```lua
function Daily.dayTime(key)
    local y, m, d = key:match("(%d+)-(%d+)-(%d+)")
    return os.time({ year=y, month=m, day=d, hour=12 })
end
```

用当天 12 点而不是 0 点，是为了避开时区切换和夏令时边界造成的跨日误判。

### 连续打卡

```lua
function Daily.markCleared(state, key)
    if state.last == key then
        return state.streak, false  -- 同日重复，不加连续天数
    end
    if Daily.isPreviousDay(state.last, key) then
        state.streak = state.streak + 1
    else
        state.streak = 1
    end
    state.last = key
    state.cleared = state.cleared + 1
    return state.streak, true
end
```

`isPreviousDay` 用 `math.floor((b - a) / 86400 + 0.5) == 1`，带四舍五入容差，容忍几分钟的时钟漂移。

## 4.5 题库验收：`bank_check.lua`

生成完题库不能直接用，要验收每道题是否：

1. 真的是唯一解（`Sudoku.countSolutions(puzzle, 2) == 1`）；
2. 技巧等级落在目标档位；
3. 已知数个数在合理区间。

专家档特殊：允许「基础技巧解不完」（`allowUnsolved`），因为这类题本来就需要更高级的推理。

## 4.6 与会话状态衔接

`board.lua` 的 `reset` 按优先级选题：

```lua
function Board:reset(difficulty, opts)
    if opts and opts.daily then
        local key = Daily.today()
        local count = PuzzleBank.count(difficulty)
        puzzle = PuzzleBank.pickAt(difficulty, Daily.indexFor(key, count))
    else
        puzzle = PuzzleBank.pick(difficulty) or Sudoku.generate(difficulty)
    end
    self.puzzle = puzzle
    self.solution = Sudoku.solve(puzzle)  -- 一律反解，不信任外部
end
```

注意最后一行：**solution 总是由 puzzle 反解得到**，即使题库附带了答案也不用。这是「不信任派生数据」原则的体现——反解一次就能验证题目合法，也避免题库答案写错。

## 4.7 本篇小结

- 离线题库解决生成性能问题：生成器 → 验收器 → 内置数据。
- 抽题避免连续重复，返回副本防污染缓存。
- 每日一题用日期字符串哈希 + 取模选题，无需服务端。
- 中午取时间避开时区边界；连续打卡带容差判断。
- `solution` 一律由 `puzzle` 反解，不信任任何外部答案。
