# 03 · 人类技巧评分器

> 本篇目标：理解四档难度背后的技巧分级逻辑，以及「提示」为什么能做到可解释。

## 3.1 为什么需要技巧评分器

数独难度没有客观标准。一道题已知数少，不一定难；已知数多，也可能藏着一个只有高级技巧才能突破的死结。

这个项目选择用**解题所需的最高级技巧**来定义难度——因为这与玩家的主观体验最直接相关：

- 简单档：只要会「看哪一格能填什么」就能通关；
- 普通档：要会「找某个数字在某行/列/宫的唯一落点」；
- 困难档：要会区块排除；
- 专家档：要用到数对，甚至基础技巧推不动。

`scripts/game/rating.lua`（448 行）就是这个评分器。它模拟人类解法，而不是暴力求解。

## 3.2 状态表示：`State`

```lua
local State = {}
State.__index = State

function State.new(puzzle)
    local vals, cands = {}, {}
    for i = 1, 81 do
        vals[i] = puzzle[i]
        cands[i] = puzzle[i] == 0 and FULL or 0
    end
    -- ...
end
```

- `vals[i]`：格子里已确定的数字（0 表示空）。
- `cands[i]`：位掩码形式的候选集。

每确定一个数字，就从它的 20 个关联格（同行、同列、同宫）的候选集里清掉这个位：

```lua
function State:place(idx, v)
    self.vals[idx] = v
    self.cands[idx] = 0
    for _, peer in ipairs(PEERS[idx]) do
        self.cands[peer] = self.cands[peer] & ~bitOf(v)
    end
end
```

`PEERS[i]` 是预计算的关联格列表（每格约 20 个）。

## 3.3 四层技巧

### L1 唯一候选（Naked Single）

某格的候选集里只剩一个数字——最直接的情况。

```lua
local function tryNakedSingle(s)
    for i = 1, 81 do
        if s.vals[i] == 0 then
            local m = s.cands[i]
            if popcount(m) == 1 then
                local v = maskToDigit(m)
                return { idx = i, value = v, level = 1,
                         reason = "这一格只剩 " .. v .. " 可以填" }
            end
        end
    end
end
```

### L2 唯一位置（Hidden Single）

在某个行/列/宫里，数字 v 只能放在某一格——即使那格还有别的候选。

```lua
local function tryHiddenSingle(s)
    for _, unit in ipairs(UNITS) do  -- 9 行 + 9 列 + 9 宫
        for v = 1, 9 do
            local spots, last = 0, 0
            for _, i in ipairs(unit.cells) do
                if s.vals[i] == 0 and (s.cands[i] & bitOf(v)) ~= 0 then
                    spots, last = spots + 1, i
                end
            end
            if spots == 1 then
                return { idx = last, value = v, level = 2,
                         reason = unit.label .. "只剩一格能填 " .. v }
            end
        end
    end
end
```

`UNITS` 预存了 27 个单元，每个含 `{cells, set, kind, label}`，`label` 直接用于提示文案（如「第 3 行」）。

### L3 区块排除（Locked Candidates）

两种形态：

- **Pointing**：在某宫里，数字 v 的所有候选都落在同一行（或列）→ 该行（列）在宫外的格子可以排除 v。
- **Claiming**：在某行（列）里，数字 v 的所有候选都落在同一宫 → 该宫的其他行（列）可以排除 v。

```lua
-- pointing 示意
for _, box in ipairs(BOX_UNITS) do
    for v = 1, 9 do
        local rows = collectRowsWithCandidate(box, v)
        if #rows == 1 then
            for _, i in ipairs(ROW_UNITS[rows[1]].cells) do
                if not inBox(i, box) then
                    eliminate(s, i, v)  -- 宫外同行格排除 v
                end
            end
        end
    end
end
```

这里曾经出过一个 bug：排除循环的 `rowHit/colHit` 变量被覆盖，导致过度排除。修复方式是用「分析结果必须能走到真实解」做校验。教训是：**技巧模拟代码本身也需要测试**，不能只看它有没有抛错。

### L4 数对（Naked Pair）

同一单元里，两格的候选集完全相同且都只有两个数字 → 这两个数字必然分属这两格，其余格可以排除它们。

```lua
local function tryNakedPair(s)
    for _, unit in ipairs(UNITS) do
        for a = 1, #unit.cells do
            for b = a + 1, #unit.cells do
                local ia, ib = unit.cells[a], unit.cells[b]
                if popcount(s.cands[ia]) == 2 and s.cands[ia] == s.cands[ib] then
                    if eliminateFromUnit(s, unit, {ia, ib}, s.cands[ia]) then
                        return { level = 4, reason = "发现数对，排除同单元其他格" }
                    end
                end
            end
        end
    end
end
```

## 3.4 定级入口：`analyze`

```lua
function Rating.analyze(puzzle, opts)
    local s = State.new(puzzle)
    local level, steps = 0, 0
    while s:emptyCount() > 0 and steps < 400 do
        local step = tryNakedSingle(s)       -- L1 优先
                  or tryHiddenSingle(s)      -- 然后 L2
                  or tryLockedCandidates(s)  -- 然后 L3
                  or tryNakedPair(s)         -- 最后 L4
        if not step then
            if opts and opts.onStall then opts.onStall(s) end
            break
        end
        level = math.max(level, step.level)
        s:place(step.idx, step.value)
        steps = steps + 1
    end
    return { solved = s:emptyCount() == 0, level = level,
             remaining = s:emptyCount(), steps = steps, vals = s.vals }
end
```

三个设计要点：

1. **按 L1→L4 优先级尝试**，先用简单技巧，用尽才上高级技巧。这样 `level` 记录的是「必需的最高级技巧」。
2. **`steps < 400` 上限**：防止病态题目让分析卡死。
3. **卡住时回调 `onStall`**：题库验收脚本用它来接受「专家档基础技巧解不完」。

## 3.5 提示的两套接口

```lua
-- 完整分析，用于生成时定级
Rating.analyze(puzzle)

-- 只找下一步，用于游戏内提示
Rating.nextStep(puzzle)
-- → { idx=..., value=..., level=..., reason="第 3 行只剩一格能填 7" }

-- 自动候选显示
Rating.candidates(puzzle)
-- → { [idx] = {1,3,5}, ... }
```

`nextStep` 只做 L1/L2 是有意的：**提示应该给出玩家能理解的推理**，而不是甩一个高级技巧的结论。当专家局连 L1/L2 都找不到时，`main.lua` 会弹一个兜底 toast（「这步需要更高级的技巧，先试试别的格子」）。

游戏里的提示是两段式的：

1. 点「提示」→ `board:requestHint()` 调 `Rating.nextStep`，只记下 `hintIdx/hintReason`，**不填数字**；棋盘高亮那一格并弹出理由；
2. 再点一次 → `board:applyHint()` 才真正落笔。

这样提示是「指路」而不是「代做」。

> 一个小瑕疵：键盘 `H` 键走的是旧接口 `board:hint()`，直接填答案，和按钮行为不一致。这是历史遗留，教程如实记录，改造时值得统一。

## 3.6 本篇小结

- 难度 = 解题所需的最高级技巧（L1 唯一候选 / L2 唯一位置 / L3 区块排除 / L4 数对）。
- `State` 用位掩码维护候选集，`place` 时清理关联格。
- `analyze` 按技巧优先级逐层尝试，记录最高用到的 `level`。
- `nextStep` 只做 L1/L2，配合两段式提示，保证提示可解释。
