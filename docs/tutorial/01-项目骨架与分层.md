# 01 · 项目骨架与分层

> 本篇目标：看懂项目目录为什么这样切分，理解逻辑层 / 表现层的边界，并跑通第一份自检。

## 1.1 先看分层

这个项目只有 20 来个业务文件，但切分得很刻意：

```
main.lua  ──→  game/*（纯逻辑）  ──→  ui/*（纯表现）
                    │                    │
                    └── theme.lua ←──────┘（共享常量）
```

- **`game/*` 是纯逻辑**：数独生成、难度评分、棋盘状态、成绩、设置、每日题。它们不引用 `UI`、不碰 `SoundSource`、不知道屏幕尺寸。这意味着它们可以在没有引擎的环境下单独跑测试。
- **`ui/*` 是纯表现**：网格怎么画、按钮什么颜色、弹层何时出现。它们从 `board` 读状态，通过回调把用户操作交回 `main`。
- **`main.lua` 是胶水层**：组装 UI、分发输入、驱动主循环、决定什么时候存档、什么时候弹窗。

这个分层带来的直接好处：当「简单档也挺难」这个反馈出现时，我们只改了 `rating.lua` 和 `sudoku.lua` 的定级规则，`ui/*` 一行没动。

## 1.3 依赖方向

```
main
 ├── game.board ──→ game.sudoku ──→ game.rating
 │       ├──→ game.puzzle_bank
 │       └──→ game.daily
 ├── game.records ──→ game.daily + game.settings
 ├── game.storage
 ├── game.sfx
 └── ui.* ──→ ui.theme + urhox-libs/UI
```

关键约束：**箭头不反向**。`sudoku.lua` 不知道 `board` 的存在，`board.lua` 不知道自己会被怎么画。改棋盘绘制逻辑时，不需要担心破坏题目生成。

## 1.4 跑第一份自检

`scripts/dev/selftest.lua` 是这个项目的「行为规格说明书」。它不启动 UI，直接断言核心逻辑：

```lua
-- scripts/dev/selftest.lua 片段
check(Sudoku.countSolutions(puzzle, 2) == 1, d.key .. " 题目不是唯一解")
```

运行方式（在 `sudoku` 目录下）：

```bash
NODE_OPTIONS="" npx -y @taptap/maker@latest preview validate \
  --target-dir "<项目绝对路径>/sudoku" \
  --entry dev/selftest.lua --mode validate --json
```

输出里看到 `result: PASS`、`total_errors: 0` 就说明逻辑层完好。这份自检覆盖了 14 类行为，后面各篇会逐一讲到它们对应的实现。

> 为什么加 `NODE_OPTIONS=""`？因为某些 Node 版本的安全 shim 会干扰 Maker CLI 的文件删除操作。这是 TapTap Maker 本地开发的一个实用小技巧。

## 1.5 配置在哪里

`.project/project.json` 是 Maker 工程的核心配置：

```json
{
  "project_id": "m_1d8f",
  "entry": "main.lua",
  "version": "1.0.8",
  "taptap_publish": {
    "title": "一格一局",
    "category": "trivia",
    "screen_orientation": "portrait",
    "app_platforms": "1,2",
    "app_id": 1012043,
    "description": "...",
    "trial_note": "..."
  }
}
```

`screen_orientation` 这类字段属于**发布配置**，改完要重新打包才能生效——它是横屏还是竖屏，不是靠代码里某行 `setOrientation` 决定的。

`.project/settings.json` 里的 `asset_dirs` 把 `assets/` 映射为资源根目录，所以音效路径写的是 `audio/place.wav` 而不是 `assets/audio/place.wav`。这个细节在第 10 篇讲音效时会用到。

## 1.6 本篇小结

- 逻辑层与表现层分离，是后面所有设计的前提。
- `selftest.lua` 是安全网，改代码前先跑一遍，改完再跑一遍。
- 横竖屏、游戏名、商店文案属于发布配置，不在 Lua 代码里。
