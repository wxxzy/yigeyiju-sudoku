# 05 · 棋盘会话状态机

> 本篇目标：理解一次落子如何改变棋盘状态，撤销为什么是「快照」而不是「反向操作」，以及存档如何做到不信任派生字段。

## 5.1 状态字段一览

`scripts/game/board.lua` 是一个 ~530 行的状态机，核心字段：

```lua
{
    puzzle, solution,          -- 题目 / 答案
    values, notes, wrong,      -- 玩家填的数 / 笔记 / 是否填错
    selected,                  -- 当前选中格（1–81）
    history,                   -- 撤销栈
    mistakes, mistakeLimit,    -- 错误次数 / 上限（0=不限）
    elapsed, started, paused,  -- 计时状态
    solved, failed,            -- 结局标记
    hintsUsed, hintIdx, hintReason,
    notesMode, showCandidates, autoCleanNotes,
    dailyKey,                  -- 每日题日期（普通局为 nil）
    lastAction,                -- 给表现层做反馈的动作类型
}
```

`lastAction` 的取值：`place / wrong / erase / hint / note / undo / restore`。表现层根据它决定 flash 什么颜色、播什么音效。

## 5.2 一次落子的完整流程

`Board:input(n)` 是统一入口：

```lua
function Board:input(n)
    local idx = self.selected
    if not idx or self.solved or self.failed or self.paused then return end

    if self.notesMode then
        -- 笔记模式：切换候选标记
        self.notes[idx][n] = not self.notes[idx][n]
        self.lastAction = "note"
        return
    end

    -- 1. 预判结果与需要清理的笔记
    local willBeCorrect = (n == self.solution[idx])
    local cleanList = self:notePeersOf(idx, n)

    -- 2. 整体入栈（主格 + 被连带清理的笔记格）
    self:pushHistory(idx, cleanList)

    -- 3. 写值、清笔记
    self.values[idx] = n
    self.notes[idx] = {}
    for _, j in ipairs(cleanList) do self.notes[j][n] = nil end

    -- 4. 判定对错
    self.wrong[idx] = not willBeCorrect
    if not willBeCorrect then
        self.mistakes = self.mistakes + 1
        if self.mistakeLimit > 0 and self.mistakes >= self.mistakeLimit then
            self.failed = true
        end
    end

    self.lastAction = willBeCorrect and "place" or "wrong"
    self.started = true
    self:checkSolved()
end
```

几个细节：

- **同格同数字 = 清除**：`if self.values[idx] == n then self:erase() end`，符合玩家直觉。
- **自动清笔记**：填下一个数字后，同行列宫里该数字的笔记会被清掉（`autoCleanNotes` 开关控制）。
- **`started` 一旦为真就不再回头**：开始计时后不会因为擦除而停止。

## 5.3 撤销：快照而非反向操作

这是状态机里最重要的设计。

如果撤销只是「把数字擦掉」，那么这次落子连带清理的 5 个笔记格就回不来了。所以撤销栈存的是**整组快照**：

```lua
local function cellSnapshot(idx)
    return { idx = idx, value = self.values[idx],
             notes = copyNotes(self.notes[idx]), wrong = self.wrong[idx] }
end

function Board:pushHistory(idx, extra)
    local snap = { cellSnapshot(idx) }
    for _, j in ipairs(extra or {}) do
        snap[#snap + 1] = cellSnapshot(j)
    end
    self.history[#self.history + 1] = { cells = snap, mistakes = self.mistakes }
    if #self.history > 100 then table.remove(self.history, 1) end
end

function Board:undo()
    local item = table.remove(self.history)
    if not item then return false end
    for _, s in ipairs(item.cells) do
        self.values[s.idx] = s.value
        self.notes[s.idx] = s.notes
        self.wrong[s.idx] = s.wrong
    end
    self.mistakes = item.mistakes  -- 错误次数也一起回滚
    self.selected = item.cells[1].idx
    self.solved = false
    self.lastAction = "undo"
    return true
end
```

三个要点：

1. **连带影响的格子一起入栈**——填数和清笔记是一次原子操作；
2. **错误次数一起回滚**——否则撤销后错误数只增不减，玩家会冤枉；
3. **栈深上限 100**——防止长时间游玩内存无限增长。

## 5.4 提示的两段式设计

```lua
function Board:requestHint()
    local step = Rating.nextStep(self.puzzle)
    if not step then return false end
    -- 只记录，不落笔
    self.hintIdx = step.idx
    self.hintReason = step.reason
    self.hintsUsed = self.hintsUsed + 1
    self.lastAction = "hint"
    return true
end

function Board:applyHint()
    -- 二次确认后，用 nextStep 真正填入
    local step = Rating.nextStep(self.puzzle)
    if step then self:inputAt(step.idx, step.value) end
    self:clearHint()
end
```

`requestHint` 只告诉玩家「为什么这一格能确定」，玩家点击确认后 `applyHint` 才落笔。这把「提示」从替玩家做题，变成了教玩家怎么做题——这是产品层面最重要的一个决策。

## 5.5 计时与失败

```lua
function Board:tick(dt)
    if self.started and not self.solved and not self.failed and not self.paused then
        self.elapsed = self.elapsed + dt
    end
end
```

暂停时 `paused=true`，计时暂停，棋盘被遮罩盖住防止玩家继续推演。

失败判定在 `input()` 里：当 `mistakeLimit > 0` 且 `mistakes >= limit` 时置 `failed=true`。设置里 `LIMIT_STEPS = {0, 3, 5}`，0 表示不限（默认）。

## 5.6 序列化：不信任派生数据

`serialize()` 只存纯数据，**不存 solution**：

```lua
function Board:serialize()
    return {
        v = 1, difficulty = self.difficulty,
        puzzle = self.puzzle, values = self.values,
        notes = flattenNotes(self.notes),
        wrong = boolToNum(self.wrong),
        mistakes = self.mistakes,
        elapsed = math.floor(self.elapsed),
        hints = self.hintsUsed,
        selected = 0,           -- 不存选中位置
        daily = self.dailyKey,
    }
end
```

`restore(data)` 的防御性极强：

```lua
function Board:restore(data)
    if not isGrid(data.puzzle) then return false end
    self.puzzle = data.puzzle
    self.solution = Sudoku.solve(data.puzzle)  -- 反解，不信任存档
    -- 已知格强制以 puzzle 为准（防止玩家改存档给自己填答案）
    for i = 1, 81 do
        if self.puzzle[i] ~= 0 then self.values[i] = self.puzzle[i] end
    end
    self.wrong = recomputeWrong(self.values, self.solution)
    -- ...
    self.solved = self:checkSolved()  -- 重判，不信任存档里的 solved
    return true
end
```

这套设计让存档篡改（改 `solved`、改 `wrong`、伪造答案）基本无效。

## 5.7 本篇小结

- `lastAction` 是状态机与表现层之间的轻量协议。
- 撤销栈存「整组快照」而非单个格子的反向操作，保证填数+清笔记原子回滚。
- 错误次数也随撤销回滚。
- 提示分 `requestHint` / `applyHint` 两步，先解释再落笔。
- 存档不存答案、不信任 `solved`，一切派生数据重算。
