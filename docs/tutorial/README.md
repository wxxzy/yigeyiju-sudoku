# 一格一局 · TapTap 小游戏开发教程

> 从一道数独题开始，逐步构建一款可上架的竖屏小游戏。

**[▶ 试玩成品](https://www.taptap.cn/app/1012043)**（TapTap 试玩版）

这是一套**按实现顺序编排**的教程，配套一个已经开发完成、已在 TapTap 上线试玩的开源项目「一格一局」（原名「唯一解」）。技术栈是 **Lua 5.4 + UrhoX 引擎 + TapTap Maker**，全程不依赖复杂工程环境。

## 为什么是这套教程

市面上多数小游戏教程只讲「怎么把界面摆出来」，很少讲：

- 怎么保证数独题**真的只有唯一解**；
- 怎么把「简单 / 普通 / 困难 / 专家」做成**可解释、可验证**的技巧分级，而不是拍脑袋；
- 怎么在无本地文件权限的沙盒里做**存档**；
- 怎么在引擎的 `nan`、`string.format`、异步回调等陷阱里稳定跑起来。

这个项目把这些问题都踩过一遍并留下了可读的代码。教程的目标不是让你复制一遍，而是**理解每个模块为什么这样设计**，然后能自己改造。

## 快速开始

```bash
# 1. 安装 TapTap Maker CLI（若尚未安装）
npx -y @taptap/maker@latest --help

# 2. 在 sudoku 目录运行逻辑自检（不启动 UI）
NODE_OPTIONS="" npx -y @taptap/maker@latest preview validate \
  --target-dir "<项目绝对路径>/sudoku" \
  --entry dev/selftest.lua --mode validate

# 3. 本地预览游戏
NODE_OPTIONS="" npx -y @taptap/maker@latest preview run \
  --target-dir "<项目绝对路径>/sudoku"
```

> 注意：项目依赖 TapTap Maker 的 UrhoX 运行时与 `urhox-libs`，单独用标准 Lua 解释器无法运行 UI 部分。但 `scripts/game/sudoku.lua`、`rating.lua`、`board.lua` 等纯逻辑模块不依赖引擎，可单独测试。

## 核心设计原则

1. **逻辑与表现分离**。`game/*` 不引用 UI，`ui/*` 不碰业务规则。这样算法可以脱离引擎测试。
2. **难度是可解释的**。四档难度对应四种人类解题技巧，不是「多挖几个洞」。
3. **不信任派生数据**。存档不存答案（反解得到）、不信任 `solved`（重算得到）。
4. **一切失败都要优雅降级**。云端不可用就用内存、音效加载失败就静音、布局尺寸是 nan 就跳过本帧。
5. **可测试才有底气**。`dev/selftest.lua` 把 14 类行为写成断言，改完代码跑一遍就知道有没有破坏契约。
