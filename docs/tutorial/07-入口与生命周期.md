# 07 · 入口与生命周期

> 本篇目标：理解 `main.lua` 如何组装 UI、分发输入、驱动主循环，以及横竖屏适配的关键实现。

## 7.1 全局状态为什么放模块级

UrhoX 把 `Start` / `Stop` / `HandleUpdate` 当作**全局函数**调用，不是某个对象的方法。所以长生命周期引用只能放模块级局部变量：

```lua
local board_, boardView_, keypad_, hud_, root_, boardArea_ = nil, nil, nil, nil, nil, nil
local resultShown_, pendingDaily_, failShown_ = false, false, false
local pendingDifficulty_ = CONFIG.Difficulty
local records_, settings_ = Records.new(), Settings.new()
local layoutTimer_, autosaveTimer_, saveDirty_, layoutWarned_ = 0, 0, false, false
```

这是引擎约束，不是设计偏好。理解这一点，才能明白为什么 `main.lua` 看起来「全局状态特别多」。

## 7.2 `Start()` 的顺序

```lua
function Start()
    graphics.windowTitle = CONFIG.Title
    UI.Init { theme = "default-taptap", scale = UI.Scale.DEFAULT }
    -- 三步走：Init → 建控件树 → SetRoot

    board_ = Board.new(CONFIG.Difficulty)
    records_ = Records.new()
    BuildUI()
    ApplySettings(false)

    -- 异步读存档（有保护，见第 6 篇）
    Storage.loadStats(...)
    Storage.load(...)

    FitBoard()
    SubscribeToEvent("Update", "HandleUpdate")
    SubscribeToEvent("KeyDown", "HandleKeyDown")
end
```

顺序不能乱：`UI.Init` 必须最先，`SetRoot` 必须在控件树建完之后，`FitBoard` 依赖控件已挂载。

## 7.3 `BuildUI()` 的控件树

```lua
boardView_ = BoardView.new(onCellTap)
keypad_    = Keypad.new(handlers)
hud_       = HUD.new(handlers)

boardArea_ = UI.Panel {
    flexGrow = 1,
    children = { boardView_.root, hud_.statsBar },
}

root_ = UI.SafeAreaView {
    children = {
        hud_.root,       -- 两行 HUD
        boardArea_,      -- 棋盘 + 成绩条（整体垂直居中）
        keypad_.root,    -- 数字键盘
        overlay,         -- 通关结算
        confirmOverlay,  -- 新局确认
        pauseOverlay,    -- 暂停
        settingsOverlay, -- 设置
        failOverlay,     -- 失败
        toastPanel,      -- 轻提示
    },
}
UI.SetRoot(root_)
```

几个设计点：

- **`boardArea_` 把棋盘和成绩条打包**，让它们作为一个整体垂直居中（`flexGrow=1`），成绩条始终紧贴棋盘下方。
- **`UI.SafeAreaView`** 避开刘海、圆角和 TapTap 胶囊菜单区域。
- **六个覆盖层用绝对定位**，盖在整棵树之上，模态显示时挡住棋盘防止继续推演。

## 7.4 统一刷新：`RefreshAll()`

```lua
local function RefreshAll()
    boardView_:refresh(board_)
    keypad_:update(board_)
    hud_:update(board_)
    RefreshStatsBar()
    saveDirty_ = true
end
```

任何状态变化（落子、撤销、提示、切难度）都走这一个入口。好处是表现层永远不会漏刷新，坏处是每次都要重绘全盘——对 81 格来说开销可以接受。

## 7.5 主循环：`HandleUpdate`

```lua
function HandleUpdate(eventType, eventData)
    local dt = eventData["TimeStep"]:GetFloat()
    board_:tick(dt)
    boardView_:update(dt)       -- flash 动画插值
    Sfx.tick(dt)
    hud_:update(board_, dt)

    layoutTimer_ = layoutTimer_ + dt
    if layoutTimer_ >= CONFIG.LayoutCheckInterval then
        layoutTimer_ = 0
        FitBoard()
    end

    if saveDirty_ then
        autosaveTimer_ = autosaveTimer_ + dt
        if autosaveTimer_ >= CONFIG.AutosaveInterval then
            autosaveTimer_ = 0
            SaveProgress()
        end
    end

    -- 失败与通关两条分支
    if board_.failed and not failShown_ then ... end
    if board_.solved and not resultShown_ then ... end
end
```

**失败分支**：播 `fail` 音 → 弹失败层（含「去设置里调整」引导）→ `Storage.clearProgress()` 清死局。

**通关分支**：`markSolved()` → 写记录（每日题走打卡、普通局刷新最佳）→ 播 `win` 音 → 弹结算 → 清进度。

## 7.6 输入分发

```lua
local DIGIT_KEYS = {
    [KEY_1] = 1, [KEY_2] = 2, -- ... KEY_9
}

function HandleKeyDown(eventType, eventData)
    local key = eventData["Key"]:GetInt()
    if hud_:isModalOpen() then
        if key == KEY_P or key == KEY_SPACE then TogglePause() end
        return  -- 模态打开时只放行暂停键
    end
    local digit = DIGIT_KEYS[key]
    if digit then InputDigit(digit); return end
    -- BACKSPACE 擦除 / 方向键移动 / N 笔记 / H 提示
    -- U 撤销 / R 新局 / P 暂停 / D 每日
end
```

`InputDigit(digit)` 是数字输入的统一入口，触屏键盘和物理键盘都走这里——保证两条输入路径行为一致（提示那条 `H` 键的遗留问题除外，见第 3 篇）。

## 7.7 `FitBoard()`：自适应核心

```lua
local function FitBoard()
    local ok = pcall(function()
        local w, h = boardArea_:GetComputedSize()
        if not isUsableLength(w) or not isUsableLength(h) then return end
        local availH = h - CONFIG.StatsReserve  -- 成绩条预留 42px
        local size = math.floor(math.min(w, availH, Theme.SIZE.boardMax))
        if not isUsableLength(size) or size < 80 then return end
        boardView_:setSize(size)
    end)
end
```

三个防御：

1. **`pcall` 包裹**——Yoga 布局首帧可能抛错；
2. **`isUsableLength`**——用字符串判定排除 nan/inf（见第 6 篇）；
3. **`size < 80` 时跳过**——空间太小就保持默认尺寸，不把棋盘压成一条缝。

`StatsReserve = 42` 是硬编码的成绩条高度（22 高 + 10 间距 + 余量）。改 HUD 布局时必须同步改这个值，否则棋盘会和成绩条重叠。

> 横屏改竖屏时，真正生效的是 `.project/project.json` 里的 `screen_orientation`，不是这段代码。`FitBoard` 只负责在给定方向下把棋盘算到合适大小。

## 7.8 待开局难度 vs 当前难度

`pendingDifficulty_` 和 `board_.difficulty` 是两个不同的东西：

- 玩家在 HUD 上点难度按钮，只改 `pendingDifficulty_`；
- 真正开新局时，`main` 比较两者，不同则弹确认框；
- `hud_:setPendingMismatch(true)` 用视觉提示告诉玩家「当前显示的难度还没生效」。

这样避免了误触难度按钮就直接换题、丢失当前进度。

## 7.9 本篇小结

- 全局状态放模块级是引擎约束（`Start`/`HandleUpdate` 是全局函数）。
- `UI.Init → 建控件树 → SetRoot` 顺序固定。
- `boardArea_` 打包棋盘和成绩条整体居中；六个覆盖层绝对定位做模态。
- 所有状态变化走 `RefreshAll()`，避免漏刷新。
- `FitBoard` 用 `pcall` + nan 检测 + 最小尺寸三重防御。
- 难度按钮只改「待开局难度」，真正切换要确认。
