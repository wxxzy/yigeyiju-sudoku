# 10 · 音效与引擎避坑

> 本篇目标：理解音效系统的实现，并集中学习整个项目踩过的引擎陷阱——这些经验比代码本身更值钱。

## 10.1 音效系统

`scripts/game/sfx.lua` 管理四个音效：`place`（落子）、`error`（错误）、`win`（通关）、`fail`（失败）。它们是 Python 合成的短 wav，放在 `assets/audio/`。

### 资源路径的坑

```lua
local FILES = {
    place = "audio/place.wav",
    error = "audio/error.wav",
    -- ...
}
```

路径里**没有 `assets/` 前缀**。因为 `.project/settings.json` 的 `asset_dirs` 把 `assets` 映射成了资源根目录：

```json
"build": { "asset_dirs": ["../assets", "../scripts"] }
```

写成 `assets/audio/place.wav` 反而找不到文件。

### UI-only 工程没有场景

这是音效系统最特殊的地方：数独是纯 UI 游戏，没有 3D 场景，但 `SoundSource` 必须挂在场景节点上。所以 `Sfx.init()` 自建了一个场景：

```lua
function Sfx.init()
    if tried_ then return end
    tried_ = true
    pcall(function()
        scene_ = Scene()
        root_ = Node()
        scene_:AddChild(root_)
        for key, path in pairs(FILES) do
            local source = root_:CreateComponent("SoundSource")
            local sound = cache:GetResource("Sound", path)
            source:SetSound(sound)
            source:SetSoundType(SOUND_EFFECT)
            sources_[key] = source
        end
    end)
    -- pcall 失败就静音降级，不影响游戏
end
```

**每个音效独立一个 `SoundSource`**，避免通关音被快速连播的落子音打断。

### 节流与随机音高

```lua
local MIX = {
    place = { gain = 0.35, gap = 0.035 },
    error = { gain = 0.45, gap = 0.12 },
    win   = { gain = 0.60, gap = 1.0 },
    fail  = { gain = 0.60, gap = 1.0 },
}

function Sfx.play(key)
    local m = MIX[key]
    if clock_ - (lastTime_[key] or -99) < m.gap then return end
    lastTime_[key] = clock_
    local source = sources_[key]
    if not source then return end
    if key == "place" then
        source:SetFrequency(0.965 + math.random() * 0.07)  -- 随机音高
    end
    source:Play(m.gain)
end
```

`place` 每次随机微调音高，避免连续落子听起来像机器重复。`tick(dt)` 自己累加帧时钟，不依赖 `os.clock()` 的精度。

所有加载和播放都包在 `pcall` 里——音效是锦上添花，绝不能因为它让游戏崩溃。

## 10.2 引擎陷阱清单

### 陷阱 1：nan 比较不可靠

**现象**：Yoga 布局首帧 `GetComputedSize()` 返回 nan/inf。`nan > 0` 可能返回真，`nan ~= nan` 也为真，常规比较完全不可靠。

**修复**：统一用字符串判定：

```lua
local function isFinite(v)
    return type(v) == "number"
       and not tostring(v):find("nan")
       and not tostring(v):find("inf")
end
```

项目里三处用到：`Storage.isFiniteNumber`、`main.isUsableLength`、`board_view.setSize`。

### 陷阱 2：`string.format` 被 i18n 重写

**现象**：`urhox-libs/Engine/i18n.lua` 包装了 `string.format`，`.project/i18n.json` 的 `code.concat_to_format=true` 还会把字符串拼接改写成 format。结果 `string.format("%d", 浮点)` 抛错。

**修复**：
- `main.FitBoard`：用 `..` 拼接 + `tostring`；
- `hud.fmtTime`：手写 `pad2`；
- `board.timeText`：先 `math.floor` 再 `%d`（参数是整数才安全）。

### 陷阱 3：局部函数作用域

**现象**：`main.lua` 里 `RefreshStatsBar` 想调用后面才声明的 `local function difficultyLabel`，编译时找不到。

**修复**：就地查 `Difficulty` 表，不依赖后面声明的局部函数。Lua 的 `local function` 没有提升（hoisting），必须先声明后使用。

### 陷阱 4：异步回调冲掉进度

**现象**：`clientCloud:Get` 的回调可能同步返回。如果玩家已经开始落子，同步返回的旧存档会覆盖当前进度。

**修复**：三道闸门——`saveDirty_`、`board_.started`、每日存档过期检查（第 6 篇）。

### 陷阱 5：撤销只回滚主格

**现象**：填一个数字会连带清掉同行列宫的同数字笔记。如果撤销只恢复主格数字，那些笔记就永久丢失。

**修复**：`pushHistory(idx, cleanList)` 把连带影响的格子一起入栈（第 5 篇）。

### 陷阱 6：反馈色不够醒目

**现象**：落子 flash 用浅蓝，和「同数字高亮」的浅蓝几乎一样，满盘高亮时看不到反馈。

**修复**：改用更饱和的 blue-400（96,165,250），并做像素采样验证。

### 陷阱 7：题库注释腐化

**现象**：`puzzle_bank.lua` 头注释写「每档 8 题」，实际是 20 题。

**教训**：以生成器脚本的 `PER_TIER` 常量为准，注释只能当参考。

### 陷阱 8：专家档提示求不出

**现象**：`Rating.nextStep` 只做 L1/L2，专家局可能连 L1/L2 都没有，提示按钮无反应。

**修复**：`main.lua` 弹兜底 toast（「这步需要更高级的技巧」）。这是刻意的设计取舍——提示必须可解释，宁可不给也不能瞎填。

### 陷阱 9：云变量占位符

**现象**：本地预览里 `clientCloud` 对象存在，但 `userId` 是占位值，写入不会真持久化。

**修复**：`cloud()` 同时校验 `userId` 非空（第 6 篇）。

### 陷阱 10：两套提示流程

**现象**：UI 按钮走两段式 `requestHint → applyHint`，键盘 `H` 走旧的 `board:hint()` 直接填答案。

**状态**：这是已知的历史遗留，教程如实记录。改造方向是让 `H` 键也走两段式。

## 10.3 通用避坑原则

从这些坑里可以提炼出几条普适原则：

1. **绝不信任引擎返回值的类型**——pcall + 类型检查 + 范围检查，三层防御；
2. **所有非核心功能都要能降级**——音效失败就静音、云端失败就用内存、布局异常就跳过本帧；
3. **重写过的标准库函数要当心**——`string.format` 不是你以为的那个；
4. **异步回调必须考虑「回来时世界已经变了」**——用 dirty flag 或版本号保护；
5. **状态变更要原子化**——撤销要连带回滚所有被影响的数据；
6. **注释会腐化，代码才是真相**——不确定就去跑自检、去看生成器常量。

## 10.4 本篇小结

- 音效自建 Scene，每个音效独立 SoundSource，全程 pcall 降级。
- 资源路径由 `asset_dirs` 映射决定，不带 `assets/` 前缀。
- nan 用字符串判定，`string.format` 传整数才安全。
- 异步回调、撤销原子性、反馈色饱和度，都是「看起来能跑但体验崩坏」的隐形坑。
- 核心哲学：**优雅降级 + 不信任外部输入**。
