# 02 · 数独生成与唯一解

> 本篇目标：理解如何用位掩码 + 回溯搜索生成数独题，以及为什么每一道题都保证唯一解。

## 2.1 问题拆解

生成一道数独题分两步：

1. **生成一个完整合法终盘**（1–9 在每行、每列、每宫都不重复）；
2. **挖洞**：从终盘里 progressively 擦掉数字，每擦一个都检查「剩下的题是否仍然只有唯一解」，不是就填回去。

第二步是关键。很多数独 App 的题有多解，就是缺了这一步校验。

## 2.2 位掩码加速

`scripts/game/sudoku.lua` 用 9 位整数表示「哪些数字已经用过」：

```lua
local SIZE, CELLS, FULL = 9, 81, 0x1FF  -- 0x1FF = 二进制 111111111

local function bitOf(v) return 1 << (v - 1) end
local function popcount(m)
    local n = 0
    while m ~= 0 do
        m = m & (m - 1)  -- 消掉最低位的 1
        n = n + 1
    end
    return n
end
```

- `bitOf(5)` = `1 << 4` = `0b10000`，代表数字 5。
- `popcount(mask)` 数还有几个候选数字。
- 一个格子 i 的候选集：`FULL & ~(rowMask[r] | colMask[c] | boxMask[b])`。

三个掩码数组 `ROW/COL/BOX` 是预计算的，长度 81，记录每格属于哪个行、列、宫。这样每次判断只需几次数组索引 + 位运算，比遍历 9 个元素快得多。

## 2.3 MRV：最小剩余值优先

回溯搜索最怕「选错格子顺序」导致搜索树爆炸。`pickCell` 用 MRV 策略——**每次选候选数最少的空格**：

```lua
local function pickCell(grid, rm, cm, bm)
    local best, bestN, bestCand = 0, 10, 0
    for i = 1, CELLS do
        if grid[i] == 0 then
            local cand = FULL & ~(rm[ROW[i]] | cm[COL[i]] | bm[BOX[i]])
            local n = popcount(cand)
            if n == 0 then return nil, 0 end      -- 死路
            if n < bestN then
                best, bestN, bestCand = i, n, cand
                if n == 1 then break end           -- 最优情况，提前退出
            end
        end
    end
    return best, bestCand
end
```

`n == 0` 意味着某格无数字可填，当前分支无解；`n == 1` 意味着这格只有一种填法，是最理想的分支点。这一策略让 9×9 数独的搜索几乎瞬间完成。

## 2.4 解数计数：唯一解的守门员

```lua
local function countSearch(grid, rm, cm, bm, limit)
    local idx, cand = pickCell(grid, rm, cm, bm)
    if not idx then return 1 end          -- 填满即找到一个解
    local found = 0
    while cand ~= 0 do
        local bit = cand & -cand
        local v = ...                      -- 由 bit 反推数字
        -- 放置 v，更新三个掩码，递归
        found = found + countSearch(grid, rm, cm, bm, limit)
        -- 撤销
        if found >= limit then break end  -- 够数就停，不必数完
    end
    return found
end

function Sudoku.countSolutions(grid, limit)
    limit = limit or 2
    local rm, cm, bm = buildMasks(grid)
    if not rm then return 0 end
    return countSearch(copyGrid(grid), rm, cm, bm, limit)
end
```

`limit=2` 是点睛之笔：我们只需要知道「是 0 个、1 个、还是 ≥2 个」，不需要数出准确总数。找到 2 个立刻停，大幅节省时间。

## 2.5 挖洞：每擦一格都验一次

```lua
local function dig(puzzle, target)
    local kept = countFilled(puzzle)
    local order = {}
    for i = 1, CELLS do
        if puzzle[i] ~= 0 then order[#order + 1] = i end
    end
    for _, idx in ipairs(shuffle(order)) do
        if kept <= target then break end
        local backup = puzzle[idx]
        puzzle[idx] = 0
        if Sudoku.countSolutions(puzzle, 2) == 1 then
            kept = kept - 1
        else
            puzzle[idx] = backup  -- 破坏唯一解，撤销挖洞
        end
    end
    return puzzle, kept
end
```

挖洞顺序是打乱的，否则每次生成的题长得都一样。`kept` 是剩余已知数个数。

## 2.6 难度不是「挖多少洞」那么简单

早期版本只按 `givens`（已知数个数）分档，结果用户反馈「简单档也挺难」——因为有的题已知数多，却需要高级技巧。现在的做法是多轮生成 + 技巧评分筛选：

```lua
-- scripts/game/sudoku.lua · generate()
for attempt = 1, GENERATE_ATTEMPTS do
    if os.clock() > deadline then break end
    local puzzle, solution, kept = generateRaw(cfg.givens)
    local rate = Rating.analyze(puzzle)

    local score = 0
    if rate.level >= cfg.minLevel and rate.level <= cfg.maxLevel then
        score = score + 100
    else
        score = score - 25 * math.abs(rate.level - nearestBound)
    end
    if rate.solved then
        if kept >= cfg.minGivens and kept <= cfg.maxGivens then
            score = score + 40
        else
            score = score - math.abs(kept - cfg.givens)
        end
    else
        score = score - 60
    end

    if score > bestScore then
        bestPuzzle, bestSolution, bestKept, bestRate = puzzle, solution, kept, rate
    end
    if score >= 140 then break end  -- 足够好，提前收工
end
```

四档配置（在 `sudoku.lua` 顶部的 `DIFFICULTIES`）大致是：

| 难度 | 已知数 | 所需最高技巧 |
|---|---|---|
| 简单 easy | 48 | L1 唯一候选 |
| 普通 normal | 42 | L2 唯一位置 |
| 困难 hard | 34 | L3 区块排除 |
| 专家 expert | 28 | L4 数对 / 基础技巧解不完 |

`os.clock() > deadline`（0.9 秒）是硬性时间预算，防止生成难题时卡住 UI——宁可返回当前最优解，也不让玩家对着白屏等。

> 生成难题的实测成本很高：凑齐专家档 20 道题，脚本试了 733 次。所以游戏优先从离线题库抽题，生成只作兜底（见第 4 篇）。

## 2.7 对外接口

| 函数 | 作用 |
|---|---|
| `Sudoku.countSolutions(grid, limit)` | 数解的个数，`== 1` 即唯一解 |
| `Sudoku.solve(grid)` | 返回完整解，不修改入参 |
| `Sudoku.generateSolution()` | 随机生成一个完整终盘 |
| `Sudoku.generateRaw(floorGivens)` | 挖洞，返回 `puzzle, solution, kept` |
| `Sudoku.generate(difficulty)` | 按难度生成，返回 `puzzle, solution, givens, rate` |
| `Sudoku.isPeer(a, b)` | 两格是否同行/同列/同宫 |

## 2.8 本篇小结

- 位掩码把「候选集」变成一个整数，位运算比遍历快一个数量级。
- MRV 让搜索树尽量窄；`limit=2` 让唯一解校验尽早返回。
- 挖洞时每擦一格都验唯一解，破坏唯一解就撤销。
- 难度分级靠 `Rating.analyze` 评分筛选，而不是只看已知数个数。
